# 背景

Next.js の fetch は Web 標準の API を使用しているのではなく、Next.js が拡張して提供していることは知っていたが、コード上どのようになっているのか気になったので今回調べてみました。

# 前提

前提として、Next.js が拡張しているのはサーバー上からのリクエストになるので、クライアントサイドからのリクエストはブラウザの HTTP キャッシュが適用されます。

> Next.js は Web fetch() API を拡張して、サーバー上の各要求が独自の永続的なキャッシュと再検証のセマンティクスを設定できるようにします。
> ブラウザでは、キャッシュオプションは、フェッチ要求がブラウザの HTTP キャッシュとどのように相互作用するかを示します。この拡張機能では、cache は、サーバー側のフェッチ要求がフレームワークの永続データキャッシュとどのように対話するかを示します。

https://nextjs.org/docs/app/api-reference/functions/fetch
https://developer.mozilla.org/ja/docs/Web/API/Window/fetch

# 調査内容

1. fetch 関数をパッチ適用するためのユーティリティ関数
   グローバルの fetch 関数がすでにパッチ済みか判断します。
   Symbol.for()を使用することで、文字列をキーとしたグローバル共有可能な識別子を作成できます。
   グローバルオブジェクトである globalThis で管理するため、名前衝突を避けるためにこのような設計になっていると思われます。

```ts
export const NEXT_PATCH_SYMBOL = Symbol.for("next-patch");

function isFetchPatched() {
  return (globalThis as Record<symbol, unknown>)[NEXT_PATCH_SYMBOL] === true;
}
```

パッチされていない場合は、標準の fetch を取得し重複排除機能を追加します。

そこからパッチされた fetch を作成し、グローバルの fetch を置き換えます。

```ts
// we patch fetch to collect cache information used for
// determining if a page is static or not
export function patchFetch(options: PatchableModule) {
  // If we've already patched fetch, we should not patch it again.
  if (isFetchPatched()) return;

  // Grab the original fetch function. We'll attach this so we can use it in
  // the patched fetch function.
  const original = createDedupeFetch(globalThis.fetch);

  // Set the global fetch to the patched fetch.
  globalThis.fetch = createPatchedFetcher(original, options);
}
```
