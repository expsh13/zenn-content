# なぜセキュリティ対策が重要か

まず、セキュリティ対策がなぜ重要なのかについてですが、アプリケーションに脆弱性があると下記のような損失があります。

- 経済的損失
- 法的な要求
- 利用者の損失
- 攻撃インフラ構築への加担

# 入力処理

入力段階の検証は脆弱性対策にはならない。入力検証はアプリ検証の仕様が基準のため、例えば「すべての文字を許容する」という仕様の場合は入力時点では何も防げない。
とひけ、できることとして下記がある。

- 制御文字のチェック
  改行、タブなど通常表示されることのない文字のこと。入力パラメータは文字が多いので制御文字の制限をかけるべき。input には、通常制御文字が入力できないが、textarea の場合は入力可能なので仕様として許可するかを決める。
- 文字数チェック
  データベースに格納するデータであれば、仕様として決まっているはずです。物理的な上限値がない場合でも、文字数上限を決めておくことで、脆弱性を狙った長い文字数が必要な攻撃を防げることがあります。
- 数値の最小値・最大値のチェック
  入力された数値に応じでメモリを確保するアプリケーションであれば大きな数値を指定することで、メモリ使用量が過大になり、アプリケーション応答が遅くなったりすることがあります。

# 表示処理

Web アプリケーションには外部からの入力などに応じで表示が変化する箇所があり、この部分の HTML 生成の実装に問題があると、XSS が生じる。
XSS 対策の基本として、要素内容は「<」と「&」をエスケープする。
属性値については、ダブルクウォートで囲って「<」「"」「&」をエスケープする。
